## 1. 背景与目标

在 https://ihr.chinasie.com/core/work-hours-fill-in/process/add 人工填报考勤工时费时繁琐。本项目构建：

1. **ihr-mcp**：HTTP 协议（Streamable HTTP）的 MCP 服务端，Node/TypeScript 实现，负责 SSO 自动登录、获取报工条目、提交考勤，并附带 Web 管理页面（项目↔客户映射维护）
2. **配对 skill（ihr-attendance）**：ZCode skill，编排完整流程——扫描本地 `F:\项目` 下各 doc 文件夹的工作文档 → 匹配 ihr 项目 → 生成考勤填报文档 → 用户确认后自动提交

## 3. 已确认事实（逆向结果）

### 3.1 SSO 登录机制（已完全逆向）

| 项 | 内容 |
|----|------|
| 登录页 | `https://my.chinasie.com/certification/?orgUrl=http%3A%2F%2Fihr.chinasie.com%2Fcore%2F`（赛意统一认证中心，UmiJS/React SPA） |
| 登录接口 | `POST https://my.chinasie.com/certification/api/v1/certificate/login` |
| 请求体 | `{accountId, password, isRememberMe}` |
| 密码加密 | AES-128-CBC，Pkcs7 填充，密钥 `UcksX3W5Gs579EYk`，IV `QWhShl9eGMvzoP5Y`，输出 **hex** 字符串（硬编码于 umi.js 前端） |
| 验证码 | **无**（仅"忘记密码"流程有短信/邮箱验证码） |
| 成功响应 | `{errorCode: "0", errorMsg, data: "<token>"}` |
| token 使用 | 写入 cookie `token=<data>`，域 `chinasie.com`，`isRememberMe: true` 时有效期 7 天，否则 8 小时 |
| 回跳逻辑 | 登录后带 token cookie 访问 `orgUrl`（即 `http://ihr.chinasie.com/core/`） |
| 特殊错误码 | `40009` = 密码已过期需重置 |

AES 测试向量（Node `crypto` 实测）：

|------|------------|

| `Test@123456` | `38c86f4bd3632097ad26a360796418b0` |
| `中a密1` | `3c76fb419459ca54610d530acf4d0acb` |

## 4. 总体架构（方案 A：纯 HTTP API，已确认）

```
┌─────────────┐  MCP (Streamable HTTP)   ┌──────────────────────────────┐
│  ZCode/Agent │ ───────────────────────▶│          ihr-mcp             │
│  + 配对skill │ ◀─────────────────────── │  Node/TS 单进程              │
└─────────────┘   list_projects /        │  ├─ /mcp     MCP 端点(无状态)│
     │            fill_work_hours 等     │  ├─ /api/*   Web 页面 JSON   │
     │                                  │  └─ /        Web 管理页面     │
     │ 扫描 F:\项目/*/doc/**.md          └──────────┬───────────────────┘
     ▼                                             │ axios + cookie jar
┌─────────────┐                       ┌────────────▼─────────┐   ┌──────────────┐
│ 生成考勤填报 │  ──用户确认──▶ MCP 提交 │ SSO登录 → token cookie│──▶│ ihr 系统API  │
│ 文档(md)    │                       └──────────────────────┘   └──────────────┘
└─────────────┘
```

**否决的备选**：方案 B（内嵌 Playwright 浏览器自动化）——重、慢、SSO 多级跳转调试困难；考勤填报是高频简单操作，纯 API 完全够用。

## 5. ihr-mcp 服务端设计

### 5.1 进程与路由

单 Node 进程（参考 apisql-mcp 模式）：

| 路由 | 用途 |
|------|------|
| `POST/GET/DELETE /mcp` | MCP Streamable HTTP（**无状态模式**，`sessionIdGenerator: undefined`） |
| `GET /api/status` `/api/projects` `/api/local-folders`、`POST /api/mapping` | Web 页面 JSON API |
| `GET /` | Web 管理页面（单文件原生 HTML/JS，无前端框架） |

### 5.2 MCP 工具清单（5 个）

| 工具 | 入参 | 出参 |
|------|------|------|
| `get_login_status` | 无 | `{configOk, loggedIn, username, tokenExpiresAt}` |
| `list_projects` | 无 | `{projects: [{projectCode, projectName, activityType, customer, customerSource, raw}]}` |
| `get_customer_mapping` | 无 | `{mapping: {项目编号: 客户}}` |
| `set_customer_mapping` | `{projectCode, customer}` | `{ok}` |
| `fill_work_hours` | `{entries: [{date, projectCode, activityType, hours, workContent}]}` | `{results: [{date, projectCode, success, message}]}` |

`list_projects` 的 `customer` 取值优先级：mapping.json 手动映射 > 项目名称包含本地客户文件夹名（最长匹配自动推断）> `未匹配`。

### 5.3 模块划分

```
src/
├── index.ts        # 入口：commander 参数（stdio/streamable-http、端口），http server 路由分发
├── config.ts       # config.json 加载（编译产物 dist 目录，用户名/密码/端口/projectsRoot）
├── service.ts      # 面向工具/页面的业务服务（listProjectsWithMapping 等）
├── sso/crypto.ts   # AES-128-CBC 加密（与前端一致）
├── sso/client.ts   # SSO 登录客户端（可注入 axios 实例便于测试）
├── ihr/parser.ts   # 报工条目解析（编号|名称/活动类型）
├── ihr/client.ts   # ihr API 客户端（条目列表 + 考勤提交；接口常量集中，Task 3 逆向后填充）
├── session.ts      # SessionManager：token 缓存(7天)、失效重登、cookie jar 管理
├── mapping.ts      # MappingStore：mapping.json 读写 + guessCustomer 推断
├── tools.ts        # MCP Server 定义（低阶 Server API，模式同 apisql-mcp）
└── web/
    ├── api.ts      # /api/* JSON 处理
    └── public/index.html  # 管理页面
```

### 5.4 Web 管理页面功能

- 登录状态卡片（用户名、token 到期时间、配置是否正常）
- 项目列表表格：项目编号 | 项目名称 | 活动类型 | 客户（下拉框，选项 = `F:\项目` 一级文件夹 ∪ 现有映射值）
- 修改客户下拉 → 保存到 mapping.json
- 修改后 agent 后续 `list_projects` 即拿到修正的客户映射

## 6. 配对 skill（ihr-attendance）设计

安装位置 `C:\Users\11013\.zcode\skills\ihr-attendance\SKILL.md`，源文件在仓库 `skill/ihr-attendance/SKILL.md`。

流程：

1. `get_login_status` 检查登录态，失败提示用户检查 `~/.ihr-mcp/config.json`
2. `list_projects` + `get_customer_mapping` 获取项目与映射
3. 确定报工周期（默认当月，用户可指定）
4. 扫描 `F:\项目` 下 `*/doc/` 内的工作文档（同时匹配前缀日期 `yyyymmdd-xxx.md` 与后缀日期 `xxx-yyyymmdd.md` 两种命名；跨月周期按月扫描合并；mtime 补扫兜底）
5. 读取文档标题/首段，归纳每天工作内容
6. 项目匹配：客户文件夹名 ⊆ 项目名称 → 匹配；映射表优先；不确定项列出问用户
7. 生成考勤填报文档 `F:\项目\doc\yyyymmdd-考勤填报-YYYY年M月.md`：

```markdown
# 2026年9月考勤填报（待确认）

| 日期 | 工时 | 项目编号 | 活动类型 | 工作内容 |
|------|------|---------|---------|---------|
| 2026-09-01 | 8 | SD26040155 | 项目执行 | 方正微QMS：修复xx（doc/20260901-xxx.md） |
```

默认规则：工作日 8 小时、周末不填、一天多项目按文档量比例拆分（标注"建议"待用户调整）。

8. **停下等用户确认/修改文档**（硬性关口）
9. 确认后解析表格 → `fill_work_hours` 逐条提交 → 回报结果
10. 全部成功则在文档末尾追加 `## 已提交（时间戳）` 防重复提交

## 8. 错误处理

| 场景 | 处理 |
|------|------|
| 配置缺失/密码错误 | 工具返回明确错误信息，agent/skill 引导用户修 config.json |
| 密码过期（errorCode 40009） | `passwordExpired: true` 标记，提示去 SSO 页面重置密码 |
| token 过期 | SessionManager 自动重登一次后重试 |
| ihr 提交单条失败 | 逐条返回结果，失败条目带 ihr 原始 errorMsg，agent 汇报 |
| 重复提交 | 考勤文档"已提交"标记 + 文档中日期去重 |
| 接口逆向漂移（ihr 改版） | 接口路径/字段集中在 ihr/client.ts 常量区，修复成本低 |

## 10. 风险与开放问题

| 风险 | 缓解 |
|------|------|
| ihr 登录后接口未逆向（唯一硬依赖） | 实施计划 Task 3，用户提供账号实测；静态 JS 分析 + 浏览器 XHR 记录双路兜底 |
| 条目格式与假设有出入 | 解析器 TDD，Task 3 保存真实样例到 test/fixtures |
| 一天跨多项目工时拆分不准 | 只生成"建议值"，最终以用户确认的文档为准 |
| 法定节假日无法自动判断 | skill 列出当月疑似节假日提醒用户确认 |
