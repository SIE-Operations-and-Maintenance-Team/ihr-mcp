## 原则

- 本 skill 只编排流程、调用 ihr MCP 工具、与用户交互；**不读写任何配置文件，不接触用户名密码**（凭据由 ihr-mcp 服务端管理）
- **不含任何硬编码路径与地址**：本地路径一律动态取自 MCP 工具返回值——项目根目录用 `get_config` 的 `projectsRoot`，配置文件位置用 `get_login_status` 的 `configPath`
- 不假设 MCP 服务的地址与端口（注册与连接由所用 MCP 客户端配置管理，agent 只按工具名调用）
- 适用于任何支持 MCP 的 agent（ZCode、Claude Code 等），不绑定特定工具

## 术语

| 术语 | 定义 |
|------|------|
| 实际(h) | 从工作文档归纳的原始工时，用于核对，不直接提交 |
| 报工(h) | 按阶梯取整规则（累计 ≥2 报 4、>4 报 8、<2 同项目跨日累积）换算后的提交值，`fill_work_hours` 解析此列 |
| 项目×日期 | 工时聚合粒度：项目编号 + 自然日 |
| 项目简称 | projectsRoot 下的客户文件夹名（如 海创、中恒MES、敏卓），与项目编号一一对应 |
| 空档日 | 有工作痕迹但无任何工时行的工作日 |

## 前置条件

- 所用 MCP 客户端已注册 ihr MCP 服务（可用工具：`get_login_status` / `get_config` / `list_projects` / `get_customer_mapping` / `set_customer_mapping` / `fill_work_hours`）
- **可用性探测**：先调用 `get_login_status`；若返回 Tool not found（工具未注册或会话工具快照未刷新），提示用户重连或重启 ihr-mcp 并刷新会话工具后重试，**终止本轮**

## 流程

### 1. 检查并获取数据

依次调用 MCP 工具：

1. `get_login_status`（同时完成可用性探测）：若返回 `configOk=false`，**停止流程**，按返回的 `configPath` 指导用户填入 username/password 并重启 ihr-mcp 服务后重试本步（agent 不代填、不读该文件）
2. `get_config`：记下返回的 `projectsRoot`（下文记作 `<P>`，本流程所有本地路径基于它）
3. `list_projects`：项目条目列表；`get_customer_mapping`：映射表

### 2. 确定报工周期

默认当月；用户指定范围则按指定值（"上周"、"9月"、"2026-09-01~09-15"）。换算成起止日期。

### 2.1 填报规则（生成文档前确认）

- **工时口径（默认）**：阶梯取整 + 单日 ≤8h 硬约束——按项目×日期累计实际工时 H：**≥2 报 4、>4 报 8、<2 同项目跨日累积后再取档**；单日各项目报工合计 ≤8h
- 用户也可指定按实际值填报，或定额式填报（某项目报 N 人天，走 5.1 排期）；口径一经确认写入文档头部，后续变更须全量重算并提示
- 明细表**双列**显示：实际(h)（核对用）+ 报工(h)（提交值）

### 2.2 节假日缓存（每年每年份只拉取一次）

对报工周期涉及的每个年份 `<Y>`，检查缓存文件 `<P>/doc/holidays-<Y>.json`：

- **已存在** → 直接读取使用，不再联网
- **不存在** → 用 web 工具拉取 holiday-cn 年度数据并**原样落盘**：先 `https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/<Y>.json`，失败换 jsDelivr 镜像 `https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/<Y>.json`
- **落盘前校验**：JSON 可解析、`year` 字段 = `<Y>`、`days` 非空，防止错误内容被缓存（缓存损坏时删文件重拉即可）
- **拉取失败降级**（含次年公告未发布导致 404，国务院通常 11~12 月发布次年安排）：不阻塞流程，第 5 步回退"疑似节假日列表 + 用户确认"，并在确认关口注明数据来源为降级
- 缓存文件名不含 `YYYYMM` 六位月份且非 `.md`，不会被第 3 步工作文档扫描命中
- **用法**：按周期起止过滤 `days`——`isOffDay=true` 为放假日（报 `加班`），`isOffDay=false` 为调休上班日（落在周末也报 `工时`）；`papers` 字段含国务院公告原文链接可追溯

### 3. 扫描工作文档

`<P>` 用第 1 步的 projectsRoot 替换。按所用 shell 选一种（示例为 2026 年 9 月；同时匹配前缀日期 `20260901-xxx.md` 与后缀日期 `bug-diagnosis-xxx-20260901.md` 两种命名习惯）：

Git Bash / WSL / 类 Unix shell：

```bash
find "<P>" -maxdepth 4 -type d -name doc | while read -r d; do
  find "$d" -type f \( -name "202609*.md" -o -name "*-202609*.md" \)
done
```

Windows PowerShell：

```powershell
Get-ChildItem "<P>" -Depth 3 -Directory -Filter doc | Where-Object { $_.Name -ceq 'doc' } | ForEach-Object { Get-ChildItem $_.FullName -Recurse -File -Filter *.md } | Where-Object { $_.Name -match '^(202609\d\d-.*|.*-202609\d\d)\.md$' } | ForEach-Object FullName
```

> 工作文档位于 projectsRoot 深度 ≤4 的 `doc` 目录内（doc 内部子目录不限深度），实际结构如 `<P>/doc`、`<P>/方正微/doc`、`<P>/海创/C#/doc`、`<P>/富士达/H5/elec8.3_mes/doc`。命令有意排除：更深层的 doc（如 `.superpowers` 历史基线快照）与大写 `Doc` 接口文档目录。若未来 doc 放置层级加深，把 `-maxdepth 4`（PowerShell 为 `-Depth 3`）调大一档。
> **环境兼容提示**：部分环境的 `find` 为受限别名（如 rtk，不支持 `-o`/`-not`/`-exec` 等复合谓词），报错时改用多次单模式 find 或 `while read -r d; do find "$d" ...; done` 循环写法。

周期跨月时（如"上周"横跨 8/9 月）对每个月份前缀各执行一次并合并结果。若担心仍有遗漏，用 mtime 补扫一遍与按名结果合并去重：

```bash
find "<P>" -maxdepth 4 -type d -name doc | while read -r d; do
  find "$d" -type f -name "*.md" -newermt 2026-09-01 ! -newermt 2026-10-01
done
```

逐个读取文件标题与开头约 30 行，归纳每天做了什么。若文档内容标注的实际日期与文件名不一致，以内容为准。

### 4. 匹配项目

- 优先采用映射表中 customerSource=manual 的条目
- 本地客户文件夹名出现在 ihr 项目名称中，**且该客户只对应一个 ihr 项目** → 直接匹配
- **一个客户对应多个 ihr 项目时【重点确认项】**：agent 根据 doc 文档内容给出归属判断（候选项目 + 判断依据，如"文档提到 XX 模块，属于项目 A 的范围"），**必须先向用户逐条确认项目归属，确认后才能写入考勤文档/填报**——不得自行拍板，判断错了宁可让用户指定；确认后可用 `set_customer_mapping` 写入映射表固化，下次自动匹配
- **文档归属以文件所在客户目录为准**（跨客户需求延续文档亦然）；文件名日期与内容日期不一致以内容为准，生成明细后按"日期×客户"矩阵交叉自查
- **列表中无该客户项目** → 记入"待派工清单"提示用户在 ihr 派工后**重新拉取列表**；未匹配项目的行**不写入提交范围，挂起待派工**，不得编造项目
- 列表中的干扰项（历史签单项目等）按项目名+工作内容排除并说明
- **提交前再拉一次 list_projects**，复核待提交行的项目编号与活动类型仍有效（期间可能补派工或项目下线）

### 4.1 ITSM 查询方法（itsm-manager MCP）

查工单支撑考勤内容（单号核实、历史周期梳理）时使用其 `search_tickets_by_code` / `search_tickets_by_customer_group` / `get_ticket_by_code` / `list_views`：

- **无"已解决"专用视图**：`list_views` 仅提供 待我接单/我处理中的/所有工单(seachType=7)/我发起的 等；查历史工单统一用 **seachType=7（所有工单）**
- **按客户拉全量**：`search_tickets_by_customer_group(keyword=客户名, page_size=200, page_index 逐页翻完)`，返回后**本地过滤** `statusName`（含"已解决/已关闭"）与 `resolvedTime` 落月（"X 月已解决" = resolvedTime 落在 X 月）
- **精确查单**：`get_ticket_by_code(单号)` 返回详情 + 回复轨迹（状态、提单人、支持人、主题原文）
- **主题关键词搜索不命中时换词重搜**：主题措辞与本地文档标题可能差异很大（实测"模板更新异常未读取PLM最新btw"0 条，换"PLM"命中 IM26080019）；优先用 `get_ticket_by_code` 按已知单号验证
- itsm-manager MCP 未注册时，降级为从本地《ITSM 工单核查报告》类文档提取单号与状态，并在文档中注明数据来源
- **单据选取规则**：考勤内容对应的工单优先选 **已解决/已关闭** 状态（工作完成才报）；「处理中」单据不作为已完成考勤内容

### 5. 生成考勤填报文档

写入 `<P>/doc/<今天yyyymmdd>-考勤填报-<YYYY年M月>.md`，表格格式**必须严格**如下（`类型`/`交付类型`/`实施地点` 列分别映射到 `fill_work_hours` 的 `type`/`tsDeliveryType`/`area`；**提交解析使用"报工(h)"列**）：

```markdown
# <YYYY年M月>考勤填报（待确认）

| 日期 | 项目简称 | 实际(h) | 报工(h) | 项目编号 | 活动类型 | 类型 | 交付类型 | 实施地点 | 工作内容 |
|------|---------|--------|--------|---------|---------|------|---------|---------|---------|
| 2026-09-01 | 方正微 | 6 | 8 | SD26040155 | 项目执行 | 工时 | 公司远程交付 | ODC集中交付区域（顺德） | xxx修复 |
| 2026-09-06 | 方正微 | 4 | 4 | SD26040155 | 项目执行 | 加班 | 公司远程交付 | ODC集中交付区域（顺德） | 上线值守 |
```

规则：
- 工作日默认 8 小时
- **同日+同项目+同活动类型必须合并为一行**（多任务用"；"串接，实际(h) 取各任务之和、报工(h) 按合并后累计重新取整）——服务端不允许同日同项目同任务提交多条
- `交付类型` 默认「公司远程交付」、`实施地点` 默认「ODC集中交付区域（顺德）」，用户可在确认关口前直接改表格定制。交付类型可选值：项目地交付 / 其他项目的项目地交付 / Base地交付 / 公司远程交付 / 居家远程交付。改为「项目地交付」时 `实施地点` 建议改填「自动」（提交时由服务端按项目带出）；「其他项目的项目地交付」需 areaId、文档填报暂不支持（提交会失败）；部门任务条目服务端自动忽略这两列（按 Base 地填写）
- **周末由用户确认是否填报，不静默跳过**：文档显示周末有工作痕迹 → 生成 `加班` 行（提交时 `type: "加班"`，hours 按文档量推断并标注"(建议)"），并在确认关口单独列出"周末 X 天是否填报、各报几小时"由用户决定；用户确认不填则删除这些行。无任何痕迹的周末不主动生成。**调休上班日除外**（2.2 缓存中 `isOffDay=false` 的周末，如 2026-09-20、2026-10-10）：按正常工作日报 `工时`
- **法定节假日按 2.2 缓存判定**：放假日（`isOffDay=true`）有工作痕迹报 `加班`，无痕迹不生成行、也不算空档日（法定假不用填）；缓存降级时才回退"疑似节假日列表 + 用户确认"
- 一天多项目按文档量拆分工时（如 4+4），标注"(建议)"
- **工作内容格式 `[单号：]任务描述`**：不带文档路径、不带内部流程标注（顺延来源/累积标记等）；单号获取优先级：ITSM MCP → 本地 ITSM 核查报告类文档 → 无单号留空；**来源文档相对路径移入文末"附录：来源对照"**（列：报工日期 | 来源文档 | ITSM 单号；标注不参与提交解析）
- 允许用户为某项目指定**统一工作内容**（如"FCT检测结果同步海尔功能开发"），覆盖逐日归纳；确认关口列出使用了统一内容的项目
- 工作内容控制在 1000 字内、不得含 `|` 字符（表格列边界 + 服务端字符白名单）；加班行的内容即加班原因，服务端必填
- **空档日**：工作日无任何工时行时，必须在文档中标注原因（如"待客户回复"），并提示该日在考勤上无记录的影响；法定节假日与无痕迹周末不计入空档日

**生成后自查清单（全部勾选后才进入确认关口）**：
- [ ] 扫描完整性：按名扫描与 mtime 补扫已合并核对，短命名与内容日期不一致文档已核
- [ ] 归属一致：每行文件所在客户目录 = 项目编号对应客户；已完成"日期×客户"矩阵交叉自查
- [ ] 唯一性：同日+同项目+同活动类型仅一行
- [ ] 双列一致：报工(h) = 阶梯取整(实际(h))；单日各项目报工合计 ≤8h
- [ ] 节假日/调休：`类型` 列与 2.2 缓存一致（放假日=加班、调休上班日=工时）；降级时疑似列表已生成
- [ ] 简称一致：项目简称 ↔ 项目编号对应正确
- [ ] 全字段：交付类型/实施地点非空（或"自动"）；加班行带 type=加班
- [ ] 空档日均已标注原因
- [ ] 附录：来源对照表完整（来源文档路径 + ITSM 单号），标注不参与提交解析

### 5.1 排期式填报（定额/空档场景）

当存在定额（如"某项目报 N 人天"）或空档补位需求时，按序执行：
1. **优先填充空档日**（顺带消除空档原因）
2. 超出部分按用户指定优先日期**预排**（如月末 28~30）
3. 不足时**周末加班补位**（type=加班；前提：项目已配置加班额度，否则转 4）
4. 仍不足则**挤占其他项目排期或核减定额**，须用户拍板

- 排期前读 list_projects 条目的 expectedStartDate/expectedEndDate，填报日期必须落在项目期望区间内；项目期与当月无交集的条目当月查询不可见（当月不可见=当月不在其项目期，跨月排期时注意）

**输出物**：日期移动对照表（原日期 → 新日期 → 原因），随文档留档。

### 6. 【硬性关口】等用户确认

展示文档内容并说明："请确认或直接修改文档 <路径>，完成后回复'继续'"。**未得到明确确认不得提交。**

确认关口必须**重点提示四类内容**：
- "一客户多项目"经 agent 判断归属的行——逐条列出"该客户 X 天工时归到了项目 Y（依据：…），请确认"
- 周末/节假日/调休上班日的行——是否填报、各报几小时；列出周期内节假日与调休上班日清单及数据来源（本地缓存 / 本次拉取 / 降级人工确认）
- 交付类型/实施地点两列的默认值（公司远程交付 / ODC集中交付区域（顺德））——如需改为其他类型或地点，请直接修改表格对应列
- 使用了统一工作内容的项目清单

### 7. 提交

- **执行顺序纪律**：用户确认的变更（尤其删除/移动/改项目行）必须**先修改文档、按自查清单复核通过，再提交**；提交成功后对应行不得再修改（需要改 = 走撤回重报流程）。变更含删除动作时，逐条核对删除已在文档落地（历史教训：先提交、后漏删行，靠事后复核才补上）
- **提交前再拉一次 list_projects**，复核待提交行的项目编号与活动类型仍有效
- **唯一性前置校验**：同日+同项目+同活动类型必须仅一行，违反先合并再提交
- 支持分批提交：用户指定"先报 X"时，只解析该项目行，其余标注待提交
- 解析规则：`类型` 列 工时/加班 → `type`（工时可省略，加班必须带）；`交付类型` 列非空 → `tsDeliveryType` 原样传；`实施地点` 列非空且≠「自动」→ `area` 原样传，空或「自动」→ 省略；**工时取"报工(h)"列**

```json
{
  "entries": [
    { "date": "2026-09-01", "projectCode": "SD26040155", "activityType": "项目执行", "hours": 8, "workContent": "...", "tsDeliveryType": "公司远程交付", "area": "ODC集中交付区域（顺德）" },
    { "date": "2026-09-06", "projectCode": "SD26040155", "activityType": "项目执行", "hours": 4, "workContent": "上线值守（加班原因）", "type": "加班" }
  ]
}
```

### 7.1 失败处理

| 错误消息特征 | 含义 | 处置 |
|---|---|---|
| 同一天同一项目同一任务不允许提交多条 | 文档违反唯一性约束 | 合并行后重提该条 |
| 当天剩余可填时数 0 | **该日已存在有效记录（可能就是本条）** | 先与用户核实是否已提交，勿盲目重试 |
| 实际人天大于预测人天 | 项目资源计划限制 | 外部依赖：请项目经理调整，挂起该条 |
| 超出加班最大时数【null】 | 项目未配置加班额度 | 外部依赖：请配置，或改排工作日 |
| 填报日期不在期望开始时间【X】-期望完成日期【Y】范围内 | **项目工期限制**（日期早于项目开始或晚于项目结束） | 排期前读 list_projects 的 expectedStartDate/expectedEndDate 核对项目期，勿排项目期外日期；**字段为参考，个别项目实际校验边界可能严于字段值（实测敏卓FCT 字段下界 9/1、实际拒绝 9/2 且报错下界 9/8），存疑时单条试提交探路**；若仍被拒，从报错消息提取 X/Y 记入文档；改排 [X,Y] 内日期或换项目期覆盖的工单 |
| 同批多条失败且消息雷同 | 服务端错误消息错位 | 逐条单独重提定位真实原因 |

### 8. 汇报与收尾

- 逐条汇报成功/失败，失败条目展示 message
- 文档中以**提交状态表**记录（替代单一"已提交"标记），列：`| 日期 | 项目简称 | 报工(h) | 状态[成功/失败原因/待提交] | 提交批次 |`
- 失败后仅重提失败条目；全部条目成功后在状态表顶部标注"全部完成"
